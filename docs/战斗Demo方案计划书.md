## 1. 第一版要验证什么

做一个可重复游玩的单 Boss 战斗 Demo：玩家按住鼠标左键划动，让角色挥刀；观察 Boss 的攻击，在正确时机反方向划动进行弹反；削减 Boss 生命和架势，最终获胜。玩家生命归零则失败，可以立即重新开始。

成功标准是“输入听话、攻击看得懂、弹反有反馈、打完想再试一次”。首个可玩版本以一场约 1–3 分钟的战斗为调节目标，实际时长由试玩决定。

建议先采用以下范围：

- Windows 电脑端鼠标操作，横屏，正面视角，固定站位，玩家与一个 Boss 对决。两个角色均能看见，建议玩家在画面下部、Boss 在上部，避免误做成左右侧视对打。
- 一个战斗场景，玩家武器精确跟随鼠标整条曲线，Boss 三种单次攻击。
- 玩家生命、Boss 生命和架势、弹反、破防、胜负、重开。
- 玩家由圆形头部和长方形身体组成，武器为独立的细长矩形；Boss 使用同一结构的放大版本，并有自己的武器。使用不同颜色区分双方，不需要下载或生成美术。
- 训练模式可固定 Boss 招式、放慢出招，便于学习和调参。

自由移动、跳跃、闪避、Boss 多阶段、装备、关卡、剧情与手机适配，作为后续扩展。当前不实现位移功能。角色根节点的位置、武器运动、战斗状态分离，保留将来加入移动和闪避的接口，避免建立暂时无用的大型框架。

## 2. 建议的核心规则

### 2.1 划线如何变成动作

已确认：曲线本身驱动武器运动，不能只显示曲线而让武器播放四方向固定动画。角色身体保持固定站位，武器与身体使用不同的变换节点。

首个实现采用可检验的默认映射：按住左键时，玩家刀尖在游戏视口内实时跟随鼠标位置，细长矩形武器的朝向由最近轨迹的切线决定；采样点按原顺序保留，画出对应刀迹。松开后收刀，清理本次攻击状态。玩家当前按意念控制飞刀实现，武器不依赖手臂或握柄位置；人物无法使用双手的背景仍是创作方向，不要求现在补画手臂。松开时回到独立的悬浮待机位置，保留已有收刀过渡即可。

按下时的武器定位不产生伤害或弹反，不能把待机位置到鼠标起点的瞬移算作斩击。拖动中的实际路径片段用于战斗判定。同一次按住允许反复普通命中和弹反，无需松开；每次有效结算后进入默认0.18秒的最短出刀间隔，并要求上次结算后的新运动片段符合距离、速度等要求。停在Boss身上、抖动、旧片段重放不能持续扣血。一次Boss攻击仍只结算一次弹反或对玩家的命中。空挥不启动冷却，可以先划过空处再命中Boss。松开只负责结束轨迹和收刀。

允许弧线、S 形和折返曲线，不以整条轨迹的起点到终点代替真实路径，也不使用全路径直线程度筛除曲线。攻击有效性和弹反方向采用最近短时间内的运动片段判断；静止、极短抖动、太慢的移动仍不产生攻击。

可供首次试玩的参数：

| 参数 | 初始建议 | 目的 |
| --- | --- | --- |
| 局部运动观测长度 | 最近约 80 毫秒 | 依据当下挥刀方向判弹反 |
| 有效局部移动距离 | 视口短边约 2%，并有最低速度要求 | 排除点按、轻微抖动与慢拖 |
| 弹反方向容差 | 反向左右各 35° | 允许自然手势的偏差 |
| 视觉路径处理 | 保留曲线与转折，允许低误差插值 | 刀尖跟随，不吸附四方向 |
| 动作最小间隔 | 0.18 秒 | 防止快速点击重复结算 |

以上都是调节起点，不是已经验证的最佳值。统一使用游戏视口坐标并按尺寸归一化，避免窗口缩放后操作距离变得不一致；窗口失焦、暂停、重开时清空尚未结束的手势。独立练习模式必须能关闭 Boss 攻击，分别用直线、圆弧、S 形和折线检查刀尖轨迹，而不只检查方向标签。

### 2.2 Boss 攻击与弹反的对应关系

所有方向都以玩家看到的屏幕为准，不随角色朝向或镜像翻转。

| Boss 刀刃在屏幕上的运动方向 | 玩家需要划出的弹反方向 |
| --- | --- |
| 左 → 右 | 右 → 左 |
| 右 → 左 | 左 → 右 |
| 上 → 下 | 下 → 上 |

首次训练先只做“Boss 下劈、玩家上挑”，确认好玩后再增加另外两招。

每次攻击有明确阶段：准备 → 方向预警与蓄力 → 命中 → 收招。先使用固定顺序帮助学习，再加入随机顺序。预警箭头表示 Boss 的攻击方向；训练模式额外显示玩家应划出的反方向，避免混淆两类提示。

弹反必须同时满足：

1. Boss 这一招仍未结算、未被打断。
2. 玩家当前曲线的新鲜局部运动片段符合反方向与速度要求，且最短出刀间隔已经结束；无需松开左键。
3. 该有效片段发生在弹反窗口内，不能用窗口之前的旧片段补判。
4. 玩家当前能行动，且不在动作间隔内。

初始建议：Boss 蓄力约 0.9 秒，在预计命中前最后 0.20 秒开放弹反。窗口包含命中时刻；同一更新内先处理有效输入，再结算命中。每招只结算一次。

过早的运动片段不自动储存到窗口中，过晚划动不追溯抵消已发生的伤害；局部方向错误也不算成功。弹反继续采用“正确局部方向 + 时机”，暂不要求双刀像素相交。普通攻击改为实际刀刃运动与 Boss 简单受击区域相交才命中，空挥不扣血；使用连续运动片段检查，避免快速划过时漏判。按下瞬移、静止停在 Boss 身上和恢复待机的移动不产生攻击。

成功弹反后立即取消这一招的伤害，Boss 进入短暂收招，同时削减架势。失败则到命中时刻扣玩家生命。第一版不加入“普通格挡”和“完美弹反”两级结果，先把一种成功反馈做好。

### 2.3 普通攻击、架势与破防

根据你提出的“削减躯干值”，本方案暂把它称为“架势值”：从满值向下减少，降至零时破防。它与生命是两条独立数值。

- 玩家有效挥刀实际命中 Boss 时，始终造成少量生命伤害和架势削减，包括 Boss 蓄力与攻击期间；取消“蓄力时被防住而零生命伤害”的旧规则。
- 符合弹反规则时优先结算弹反，不再叠加普通攻击伤害；一次普通命中不会自动打断 Boss，架势清空才打断进入易伤。
- 弹反主要削减架势，直接生命伤害初始设为零。
- 架势归零后，Boss 攻击被打断，进入约 2 秒的易伤状态（即破防）；实际命中时生命伤害按倍率放大。触发架势清空的这一击按命中前的正常倍率结算，从下一次命中开始享受易伤，避免同击重复结算。
- 易伤期间架势保持零，不能重复触发或无限延长易伤；结束后恢复满架势，再开始正常攻击循环。第一版不做平时自动回复，方便观察削减效果。
- Boss 生命归零优先进入胜利状态；玩家生命归零进入失败状态。胜负后停止战斗输入与攻击计时。

初始数值供搭建使用：

| 项目 | 初始值 |
| --- | --- |
| 玩家生命 | 100 |
| Boss 生命 / 架势 | 300 / 100 |
| 玩家普通攻击 | 生命伤害 10，架势削减 6 |
| 成功弹反 | 架势削减 30 |
| Boss 命中 | 玩家生命损失 20 |
| 易伤期间受伤倍率 | 2 倍（初始测试值） |

第一版仅给 Boss 架势条，玩家先只有生命条。若你希望双方都有架势、破防后触发处决，或采用“架势条积满才破防”，应在正式实现前调整这部分规则。

当前试玩重点是数值变化：界面同时显示 Boss 血量和架势的当前值/最大值，命中时显示本次生命伤害与架势削减，易伤时显示明显状态、倍率与剩余时间。补充一个与自由练刀分开的木桩测试模式：Boss 不主动攻击，但允许命中、扣血、削架势和易伤；支持重置 Boss。自由练刀继续不扣血，避免混淆两种用途。

### 2.4 美术替换与可选手臂接入

- 身体美术与战斗逻辑分离：头、身体、左臂、右臂、武器有明确的替换位置，当前几何占位仍可正常运行。
- 玩家与 Boss 都预留可选左右肩/手臂挂点，不要求现在绘制手臂。玩家飞刀与任何手臂节点都没有必需依赖；未来新增、隐藏或删除手臂不改变曲线控制。
- 武器视觉可以由细长矩形替换为贴图或独立场景，明确刀尖基准点，避免换美术后刀尖位置或受击判定漂移。
- 刀迹使用独立表现节点，允许在 Inspector 指定材质/Shader、纹理、宽度和颜色；材质为空时保留当前可见轨迹。不必提前制作最终 Shader。
- Shader 仅控制显示，不能通过材质参数反过来决定伤害、架势或弹反方向。输入采样点与用于判定的轨迹独立于视觉效果。
- 不引入完整骨骼、IK 或装备系统；做清晰、可实际挂载的接入点即可。执行后写出素材应放在哪里、挂到哪个节点、刀尖与身体原点如何对齐。

每个阶段都交付可以运行的版本。前一阶段验收通过，再推进下一阶段。

| --- | --- | --- |

## 4. Godot 中怎么组织

“场景”可以理解为由角色、画面和控制逻辑组合出的一个模块；“节点”是模块中的零件；“脚本”定义零件如何工作。第一版用 GDScript，保持少量职责明确的模块。

建议的结构：

```text
scenes/
  gesture_lab.tscn       划动练习场
  battle.tscn            战斗主场景
  player.tscn            玩家表现
  boss.tscn              Boss 表现与招式状态
scripts/
  gesture_input.gd       保留整条曲线、计算局部运动、发出路径与攻击事件
  weapon_controller.gd  刀尖位置、武器朝向、轨迹显示；与角色位置解耦
  battle_controller.gd  命中、弹反、生命、架势、胜负结算
  boss_controller.gd    选择招式、推进准备/攻击/收招等阶段
  player_view.gd        挥刀和受击表现
  battle_hud.gd         血条、提示、重开按钮、调试数据显示
data/
  combat_tuning.tres    手势阈值、伤害、窗口时长等调节参数
assets/
  placeholder/          第一版占位图形和声音
docs/
  战斗Demo方案计划书.md   本计划书
```

实现时按需要增加参数资源脚本和效果模块，不要求一次建完所有文件。

鼠标事件负责采样，`Line2D` 负责把采样点画成轨迹，武器控制器必须实际消费曲线位置更新刀尖；角色和 Boss 用独立场景，界面用 `Control` 与 `CanvasLayer`。几何形状可以用 Godot 原生绘制或节点实现。Boss 使用与当前几何身体对应的简单受击区，普通攻击做刀刃连续运动片段的相交检查；弹反仍由方向与时机决定。无需完整物理战斗系统。可在角色根下预留移动控制器位置，未来换成物理移动节点时不重写输入与伤害模块。

数据流分两支：鼠标采样点 → 武器刀尖与刀迹实时更新；带时间戳的局部运动 → 战斗规则检查 → 生命/架势变化 → 反馈更新。输入模块不直接扣血，武器绘制也不各自再扣一次血。

Boss 用有限的状态组织行为：等待、预警、攻击、收招、破防、死亡。所谓状态，就是“现在正在做哪件事、能不能接收下一件事”。Boss 的攻击时间表由一处统一维护，动画跟随它显示，避免画面刀还没落下但玩家已经扣血。

弹反停顿使用战斗暂停的统一时间规则，暂停期间不接收新战斗手势；恢复后继续剩余时间。完成一次攻击、重开或结束战斗时，使旧攻击标识失效，避免延迟回调在下一局继续扣血。

移动端以后将触摸按下、拖动、抬起转换为同样的方向指令。第一版先不同时启用鼠标模拟触摸与原生鼠标两条通道，避免一个划动触发两次。

## 5. 我需要你提供什么

用户已确认：

1. **画面方式**：正面视角、固定站位，暂不加入移动和闪避，但为后续扩展保留结构。
2. **轨迹的含义**：武器精确跟随整条曲线，不简化为四方向预设斩击。
3. **美术**：玩家与 Boss 都用圆头、矩形身体、细长矩形武器；Boss 为放大版本，共两人两武器。

用户进一步明确：普通命中会扣少量血；架势清空后进入易伤。持续时间、倍率、各次伤害与是否给玩家增加架势仍可通过试玩调整。人物无法使用双手、意念控制飞刀是目前采用的创作方向，美术接口应保留可选手臂。

之后再补充：期望偏爽快还是偏精准、喜欢的游戏或动作参考、目标设备与屏幕方向。没有美术、音乐或编程经验也可以开始；先使用占位内容。后续引入第三方素材时记录来源和许可。

你的主要工作是试玩并提供具体反馈，例如“向上划经常识别成向右”“我觉得刀到了但系统说过早”“预警箭头看不清”。我负责将反馈对应到输入、时机、规则或画面，修改后交付下一版。

## 6. Astra 讨论、Sol 执行的协作方式

按你提出的分工：当前聊天负责讨论与规则更新，用户明确要求创建一个独立的 Sol 聊天，在同一个本地 Ninja 项目中执行本次原型。执行期间当前讨论聊天不同时修改游戏代码；规则变化需要同步给执行聊天。

减少反复讨论的办法是保留三类信息：

- 本计划书：当前已经决定的玩法，以及仍待确认的选项。
- 阶段交接记录：完成项、实际验证结果、已知问题和下一步。
- 每次执行任务：明确本次范围、验收方式和停止位置。

建议在阶段 2 的首次可玩版本、阶段 3 的完整循环后，回到 Astra 评估玩法。小的脚本报错、数值调整和表现修正可以继续交给 Sol。

可直接使用的执行任务格式：

> 先阅读 `docs/战斗Demo方案计划书.md` 和最新交接记录。本次只实现阶段 X。遵守已确认的玩法规则；对未确认且会改变玩法的选择先说明。完成后运行检查，并通过 Godot/MCP 验证本阶段的操作。报告改动、测试结果、已知问题、我应如何试玩，然后更新交接记录，在本阶段结束处停下。

每次交付附一段新手说明：从哪里运行、如何操作、这次新增的节点和脚本各负责什么、在哪里调关键参数。你无需在开始前学完 Godot。

## 7. 验收时重点检查

- 圆弧、S 形、折返、斜线都能真实驱动刀尖沿曲线运动；不能只是光效跟随而武器仍播放固定动画。
- 点按、按下定位瞬移、静止和轻微抖动不产生伤害；按住不松开持续挥刀可在间隔后重复命中或弹反，旧片段不能重放刷判定。
- 转折后的弹反方向取当前局部片段，不错误使用整条轨迹的起终点向量。
- Boss 三个方向分别对应正确的反方向；左右不会因角色翻转而改变。
- 过早、窗口内、过晚、错误方向结果明确；同一 Boss 攻击只扣一次血。
- 弹反成功不会同时受伤，也不会额外结算一次普通攻击伤害。
- 空挥不扣 Boss 血；普通命中在蓄力期也扣少量血；快速划过受击区不漏判，按下瞬移不算命中。
- 架势清空准确触发一次易伤；易伤前后的同类命中伤害有可见差异；期间不重复重置倒计时，结束后架势恢复。
- 刀迹可实际挂载自定义材质，替换角色或武器视觉不改变数值判定；双方可选手臂节点缺失时仍能运行。
- 破防、死亡、暂停、失焦和重开会取消该取消的输入与攻击。
- 30、60、120 FPS 下使用按时间计算的窗口，检查边界不会因为跳帧被漏掉；同时在不同窗口尺寸下试划。
- 随机攻击模式不能只靠无脑重复同一方向稳定通关。
- 自动检查覆盖方向判定、时序和重复结算；手感、可读性、音画一致性由实际试玩验收。
- 若本机未安装导出模板，在阶段 5 安装与 Godot 4.7.2 匹配的模板；导出后再次验证，不把编辑器内运行当作导出验证。
