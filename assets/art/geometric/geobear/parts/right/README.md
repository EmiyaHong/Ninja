## 拆件方法（与正面 v2 的差异）

侧面只有一条近侧手臂，结构比正面简单，但有一个坑：**头与背部轮廓连续、无接缝**，
只能人工开边切割，所以头不是"连通域"切出来的，而是沿切割多边形取原像素。

本轮放弃了"多边形重绘 + 描边骑缝"的路线（正面 v2 用的），改为**直接取原图像素**：
每个部件 = 自己的原图像素（1:1，含描边）+ 隐藏在别的部件后面的补画。
理由是实测多边形重绘会让外轮廓系统性内移 2~7px，拼装永远有偏差；而取原像素可以做到零误差。

**补画的两条铁律**（这轮踩了两次坑）：

1. 补画不能压到**任何黑描边像素**。拼装时上层盖住下层，补画落在别件的填色区上无所谓
   （被遮住），但落在黑线上就会把线涂成青蓝/灰色 → 出现断线与色差。
2. 补画不能超出**原图不透明区**，否则拼装会多出不透明像素。

各件掩码严格互斥（从上层往下逐层扣除），所以拼装时同一像素只有一个件提供原画颜色，
不会出现"两个件都带该像素、颜色还不同"的叠色问题。

## 验收结果

- **拼装 vs 原图：alpha 差 0px，色差 11px（0.004%）**——肉眼不可辨。
  差异热力图（assembled_preview 第三栏）几乎全灰。
- **关节裂缝检测**（摆姿后，原图不透明区里除"转走件原位"之外的透明像素）：
  头转 ±15° → 0px；抬腿 30° → 0px；抬臂 90° → 0px；弯肘 90° → 0px。
- **连通性**：拼装与抬臂 90° 后整体都是单一连通体，身体不会被切断。
- **透明**：全部部件画布 1024×1024，半透明像素 0，透明区 RGB 全 0
  （源图透明区 RGB 是米白 `255,249,230`，已清零，不会在缩放/合成时泛白边）。
- **原图未动**：八方向源图、`art_manifest.json` 均未修改。

## 仍需注意的地方

- **头部切割线是人工开的**。头背在侧面上是一条连续轮廓，没有解剖分界线，
  所以切割位置（耳后 → 后颈凹 → 下巴线左端）是按结构估的。
  转头幅度超过 ±20° 时，切割线处可能看到轻微错位，游戏里建议限制在 ±15° 内。
- **颈后补画画的是纯青蓝色块**，因为侧面看不到脖子结构。抬头 15° 时
  会露出一小片青蓝，颜色与身体一致，但**没有描边**（隐藏区域按提示词允许用简单色块补齐）。
  如果要更精细，可以手工在 `torso.png` 的颈后区域补一道黑线。
- **爪与掌是同一件**（claw），三根爪不能单独转动。侧面爪与掌本来就一体连画，
  强行拆开会破坏爪根。若要爪单独动，需要手工重画爪根封口。
- **腿脚是一整件**，踝部那两条线保留在件内（原设计如此）。
- 侧面只见近侧的一条手臂和一条腿；远侧肢体被身体完全挡住，没有拆出部件。
- 其余六个方向（stand_01 ~ stand_08）需按各自方向的图单独拆，
  左侧面可以直接镜像本套。
